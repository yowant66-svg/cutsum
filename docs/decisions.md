# 工程决策记录

## D-001：长期目标按可独立验证的子计划执行

- 日期：2026-07-31
- 决策：不再按外部 Gate 文件停顿；每个内部阶段仍保持测试、提交和进度记录。
- 理由：减少交接损耗，同时保留可回滚、可审查的工程边界。

## D-002：继续在现有 main 分支提交

- 日期：2026-07-31
- 决策：沿用此前 Gate A–J 的单维护者 main 分支工作流。
- 理由：维护者明确授权直接持续实施并自行提交；开始时工作树干净。禁止重写历史和破坏性 Git 操作。

## D-003：字幕采用五层模型

- 日期：2026-07-31
- 决策：source evidence、semantic span、translation record、display unit、visual layout 分离。
- 理由：避免把 ASR cue、翻译句、时间 cue 和画面换行再次混为一体。

## D-004：体育评测优先合成或来源明确素材

- 日期：2026-07-31
- 决策：在无需 Cookie、账号、付费 API 的素材上先完成协议、算法和小规模成片。
- 理由：满足真实可运行验证，同时避免版权和账号边界。

## D-005：估算时间不得冒充真实词级时间

- 日期：2026-07-31
- 决策：cue 内按字符位置派生的时间统一记录为 `estimated`；只有完整 source cue 或真实词级证据可以记录 `exact`。
- 理由：保证同步能力的溯源表述真实，允许未来替换为真实对齐器而不破坏协议。

## D-006：教育类型信号不等于可独立入选

- 日期：2026-07-31
- 决策：教育 AUTO 先验证上下文、陈述完整性和 transcript 可靠性，再按结构性知识类型做多样化选择。
- 理由：真实 MIT transcript 证明，关键词命中可能只是“稍后会讲定义”、定理名称或指代前文；这些内容不得伪装成完整知识片。

## D-007：体育检测与高光选择分层

- 日期：2026-07-31
- 决策：音频、镜头、OCR、动作、解说和回放 Provider 只输出可追溯观察；核心负责跨模态聚合、完整性、去重与宿主意图。
- 理由：单一声音峰值或镜头切换在体育视频中误报率高，也不应让任一检测 Provider 垄断最终高光决策。

## D-008：评测通过与内容质量认可分层

- 日期：2026-07-31
- 决策：`pass@1`、`pass^3` 和 capability pass rate 只证明声明范围内的协议与确定性行为；
  synthetic 或 curated protocol 证据不得自动生成内容质量通过结论。
- 理由：开放式选段质量需要维护者观看真实输出；自动 grader 不能替代审美、叙事完整性和
  场景适用性的人工判断。

## D-009：公共 SDK 与 CLI 只保留一份用例逻辑

- 日期：2026-08-01
- 决策：`universal_cutup.sdk` 作为稳定公共导入面，复用 application SDK；CLI
  仅负责参数、文件边界、JSON 输出和退出码。
- 理由：这使宿主 Agent、Python 开发者和命令行用户共享同一选段、溯源和
  能力边界，不会因入口不同获得不同结果。

## D-010：基础竖屏构图保持确定性且不冒充检测

- 日期：2026-08-01
- 决策：V1 基础 9:16 只提供中心裁切、手工焦点、完整画面模糊背景和固定焦点；
  `tracked_focus` 保持结构化不可用。所有模式保存可重放的裁剪、焦点、锚点、安全区和理由。
- 理由：在不引入模型、私有素材或联网 Provider 的前提下先交付可预测的通用能力，同时
  避免把居中假设夸大为人物检测。复杂运动主体需要后续独立 Provider 和真实许可评测。

## D-011：输出回滚必须证明文件所有权

- 日期：2026-08-01
- 决策：所有已知输出在渲染前预检；发布继续使用 no-overwrite hard link。异常回滚只删除
  本次发布后记录的设备号/inode 仍匹配的路径，不能依据预期文件名直接删除。
- 理由：检查与发布之间存在竞争窗口。路径名相同不代表文件仍由当前 execution 所有；
  只按名称清理可能破坏另一个本地进程刚写入的结果。

## D-012：跨平台声明以 CI 配置和实际运行分层

- 日期：2026-08-01
- 决策：仓库加入 Linux、macOS、Windows 和 Python 3.11–3.13 的只读 CI；依赖 Action
  固定到 commit SHA，不包含 publish/release。未推送运行前只称“CI 已配置”。
- 理由：本地 macOS 证据不能替代 Linux/Windows runner；同时长期目标禁止当前公开推送，
  所以必须保留 configured 与 cloud-verified 的证据差异。

## D-013：工程许可证检查不等于法律确权

- 日期：2026-08-01
- 决策：REUSE、依赖 metadata、wheel/sdist 清单和工程溯源分别记录；版权主体、名称、
  早期私有参考和 benchmark 权利保持公开前强制人工/法律项。
- 理由：自动工具能证明文件标注与已知依赖状态，不能替代权利主体确认、商标检索或
  非侵权法律结论。

## D-014：离线链路必须区分项目离线与安装缓存完备

- 日期：2026-08-01
- 决策：两条用户链路不调用 Provider 或网络；安装使用 `--offline`。若目标 Python 的
  二进制依赖不在缓存，记录环境阻塞，不能用联网补包后仍称完全离线。
- 理由：Python 3.11 与 3.12 的实际缓存结果不同。wheel 为 pure Python 不代表
  pydantic-core 等传递依赖在所有解释器/平台都已有离线制品。

## D-015：distribution、Schema 与策略版本独立冻结

- 日期：2026-08-01
- 决策：内部包版本冻结为 `0.1.0rc1`；Schema 继续为 `0.1.0`；教育与体育的 Alpha
  strategy version 不随 distribution 自动升级。StrategyRecord 从包单一版本常量取值。
- 理由：包进入候选阶段只说明整体工程可安装和可复核，不代表协议破坏性升级，也不代表
  尚未完成真实检测/质量校准的 Alpha 策略突然成熟。

## D-016：内部 RC 与公开发布严格分离

- 日期：2026-08-01
- 决策：RC 交付为本地 commit、可复现 wheel/sdist、外部证据索引和不含媒体的私有 ZIP。
  不创建远程 tag、Release、PyPI 包、公开仓库或申请。
- 理由：长期目标授权的是内部可安装候选；公开动作和法律/账号协调仍是单独权限与停止条件。

## D-017：体育语义提示与 MatchState 严格分离

- 日期：2026-08-01
- 决策：确定性 transcript Provider 可以记录 `decisive_score` narrative cue，并把它作为
  DIRECTED 语义资格；该 cue 不得解释为已验证的比分变化、比赛时钟、领先变化、冠军状态或
  历史重要性。修正版 distribution 使用 `0.1.0rc2`，体育策略版本使用
  `alpha-0.2.0`。
- 理由：这能修复“只要一个绝杀却选择普通进球”的确定性错误，同时不伪造当前尚未实现的
  MatchState、OCR、音频或视觉确认。
