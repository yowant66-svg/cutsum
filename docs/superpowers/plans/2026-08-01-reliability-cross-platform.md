# 可靠性与跨平台实施计划

**目标：** 使本地执行在输出冲突、进程缺失、超时取消、路径差异和支持平台上都
失败可解释、文件不误删、临时产物可清理，并建立可重复的 CI 验证面。

**审计结论：** 当前执行记录、超时/取消状态、同文件系统临时目录和 source hash
复核已有基础。主要差距是多文件发布竞争时的所有权不明确、Windows 路径语义未被
统一拒绝、进程启动失败未结构化，以及仓库没有 CI workflow。

---

## Task 1：路径与进程失败边界

- [x] 用失败测试覆盖 Windows drive/UNC/反斜杠穿越路径。
- [x] SafePathPolicy 在所有宿主平台采用相同拒绝语义，并继续阻断子路径符号链接逃逸。
- [x] ProcessRunner 将 executable 缺失和启动失败转换为可审计 ProcessOutcome。
- [x] 能力探测在 FFmpeg/Swift 缺失时返回 unavailable，不传播系统异常。

## Task 2：候选发布、幂等与恢复

- [x] 用竞争注入测试证明失败运行不会删除既有 clip 或 subtitle。
- [x] 发布只回滚本次运行真正创建且身份未被替换的文件，保持 no-overwrite。
- [x] 候选输出集合在渲染前统一预检，减少昂贵工作后的确定性冲突。
- [x] 验证失败/超时/取消后无 `.cutup-*` 临时目录残留，部分成功记录保持真实。

## Task 3：跨平台验证面

- [x] 增加 Linux、macOS、Windows 与 Python 3.11–3.13 CI 矩阵。
- [x] 三平台均显式安装 FFmpeg 并运行完整测试；安装或能力失败会使任务失败，不伪装通过。
- [x] 文档记录 macOS 实跑、CI 尚未云端运行和未实机确认项。

## Task 4：阶段收口

- [x] 更新风险、决策、进度和 readiness。
