# CutSum public trial kit

This kit helps a real tester evaluate CutSum without sharing private media or granting account
access. A useful trial normally takes 15–30 minutes.

## Tester workflow

1. Read and run the [5–10 minute quickstart](../quickstart.md).
2. Open at least one output from each track you ran.
3. Complete the [tester checklist](tester-checklist.md).
4. Submit feedback with the
   [GitHub trial-feedback form](https://github.com/yowant66-svg/cutsum/issues/new?template=trial_feedback.yml)
   or copy the [feedback template](feedback-template.md) into a private message.

The generated `quickstart-report.json` is safe to share after the tester reviews it. Do not attach
source media, subtitles, terminal history, home-directory paths, credentials, cookies, tokens, or
private project data.

## Maintainer workflow

1. Invite only real people using [invite-template.md](invite-template.md).
2. Ask testers to report their actual environment and result, including failures.
3. Keep feedback verbatim or clearly label summaries as maintainer summaries.
4. Never create synthetic users, stars, downloads, issues, testimonials, or adoption claims.
5. Triage reproducible bugs separately from editorial preferences and feature requests.

## Evidence boundary

- Automated output confirms installation and deterministic media execution.
- A completed checklist confirms what that tester personally inspected.
- Neither one establishes universal clip quality, legal clearance, or broad adoption.
- Testers must use the synthetic quickstart or media they own or are authorized to edit.
